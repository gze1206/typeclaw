# MCP Static OAuth Client Design

## Goal

Let any HTTP MCP server that does not support Dynamic Client Registration (DCR) authenticate through TypeClaw with an operator-provided, pre-registered OAuth client, while retaining the existing DCR flow as the default.

## Scope

This feature applies to HTTP MCP servers configured in `typeclaw.json#mcpServers`. It is not Google-specific: Google Calendar is the motivating server, but any MCP authorization server with a pre-registered OAuth client can use the same configuration.

The change supports OAuth authorization-code flow with PKCE. It does not expose OAuth access tokens or refresh tokens to model-driven bash; those remain in `secrets.json#mcp` and are supplied only to the MCP transport.

## Configuration

Add an optional `oauth` object to each HTTP MCP server:

```json
{
  "name": "calendar",
  "url": "https://calendar.example.com/mcp",
  "oauth": {
    "clientId": "public-client-id",
    "clientSecret": { "env": "CALENDAR_MCP_CLIENT_SECRET" },
    "redirectUri": "http://localhost:1456/callback",
    "scope": "calendar.events"
  }
}
```

- `clientId` is required when `oauth` is present.
- `clientSecret` is optional and uses the existing `Secret` shape. It is resolved only in the host-side authentication flow and container MCP transport, never copied into a model tool argument or bash environment.
- `redirectUri` is optional. Its default is the callback URI generated by `typeclaw mcp auth`; when set, it must exactly equal the active callback URI. This prevents an operator from accidentally authorizing a client registration for a different redirect target.
- `scope` is optional and overrides the server-discovered/default OAuth scope for that server.
- `oauth` is HTTP-only. Stdio servers have their own process environment and cannot use TypeClaw's HTTP OAuth provider.

## Runtime behavior

OAuth client selection is explicit:

1. A server without `oauth` keeps the current behavior: TypeClaw supplies no client information initially, and the MCP SDK performs DCR when required.
2. A server with `oauth.clientId` supplies static client information (`client_id`, optional `client_secret`, and the configured callback URI) to the SDK before authorization. The SDK therefore uses the registered client and does not attempt DCR.
3. The static registration is configuration, not an OAuth credential. It is never persisted as an SDK-generated DCR record. OAuth tokens and discovery state continue to use `secrets.json#mcp.<server>`.
4. `typeclaw mcp auth <name> --port <n>` rejects an explicit static `redirectUri` that differs from its callback URL, with an actionable error naming the configured and requested URIs. It never silently re-registers or replaces a static client.

Static `Authorization` headers and `bearerToken` remain mutually exclusive with OAuth as today: a server carrying an Authorization header gets no OAuth provider.

## Security

- Client secrets use `Secret`, so operators can source them from an environment variable rather than place them in plaintext JSON.
- Model-driven bash does not receive the client secret, access token, refresh token, or any GWS profile directory.
- The server's existing `allowTools` and `denyTools` policy remains the authorization boundary for which MCP operations the agent can invoke. A Calendar deployment should allow only the intended calendar read/write tools.
- The server name continues to namespace stored OAuth tokens, so credentials for one MCP server cannot be used by another configured server.

## Tests

- Schema accepts `oauth` only for HTTP servers and rejects a missing `clientId` or an empty client ID.
- The OAuth provider returns configured static client information and preserves optional secret, scope, and redirect URI.
- A server without `oauth` still returns no initial client information, preserving DCR.
- The host auth flow rejects a static redirect URI that differs from the selected callback port.
- MCP connection wiring passes the static provider for HTTP transports and never adds one to stdio or static-Authorization servers.
- Existing DCR, token persistence, static bearer, and tool-gating tests remain green.

## Operational effect

An operator can configure a Google Calendar MCP server with a Google Cloud OAuth client ID, run `typeclaw mcp auth <name>` on the host, and manage Calendar through MCP tools without installing `gws` globally or exposing `~/.config/gws` to the model sandbox.
